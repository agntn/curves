## Two kinds of Weierstrass curve

Most of the package works on the short Weierstrass form, y² = x³ + ax + b, over the integers mod a prime p. That covers the toy curves of a CTF and secp256k1 alike. The difference is in what you hand over.

| | Curves you define | secp256k1 | P-256, P-384, P-521 and brainpoolP256r1 |
| --- | --- | --- | --- |
| Import | `@agntn/curves` | `@agntn/curves/secp256k1` | `@agntn/curves/p256`, `@agntn/curves/p384`, `@agntn/curves/p521`, `@agntn/curves/brainpoolp256r1` |
| Curve | `defineCurve({ a, b, p })` | fixed, from SEC 2 | fixed, from SEC 2 and RFC 5639 |
| Points | `{ x, y }` as bigints, `null` for infinity | SEC1 hex, infinity refused | SEC1 hex, infinity refused |
| Scalars | any bigint | 1 to n - 1, hex or bigint | 1 to n - 1, hex or bigint |
| Extra | lifting x, counting, listing, orders, logs | scalars mod n, lifting x | lifting x, ECDSA verification |
| Agent tool | `curves_compute` | `curves_secp256k1_compute` | `curves_p256_compute`, `curves_p384_compute`, `curves_p521_compute`, `curves_brainpoolp256r1_compute` |

Why two? A toy curve is about the group. Count the points, find an order, take a log. secp256k1 is about keys. Nobody counts its points, and a log on it is not happening.

P-256, or secp256r1, is another fixed curve: it uses SEC1 points, lifts x and checks ECDSA signatures. It's for checking other people's keys, not signing, and that limit matters. One letter separates secp256k1 from secp256r1, but here the r doesn't sign.

P-384 gives each coordinate 48 bytes, so its points take up more room than P-256's. It uses the same SEC 1 code and the same a = -3 formulas as P-256. The math doesn't change, only the ruler does.

P-521 fits each coordinate into 66 bytes, with only one bit used in the top byte. And yes, it's 521, not 512. That's not a typo.

Brainpool chose parameters without special shortcut primes. Its a is neither 0 nor -3, so it needs formulas for any a. The points look like P-256 points by length. That resemblance can fool an on-curve check too.

## And two that aren't Weierstrass

Polkadot went another way. Its accounts sign with sr25519. That's Schnorr over ristretto255, a group that sits on edwards25519. Not a Weierstrass curve at all, so it gets entries of its own. `@agntn/curves/sr25519` has keys, signatures and HDKD. `@agntn/curves/ristretto255` has the points underneath. And the agent tool? `curves_sr25519_compute`.

Monero sits on the same curve and skips the ristretto layer. Its keys are plain ed25519 points, small order ones included, so `@agntn/curves/ed25519` keeps the cofactor in view. No agent tool for that one yet, just the library.
