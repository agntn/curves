## Try it without installing anything

The [playground](/playground) imports `@agntn/curves` into the page and runs the tool executors right there. Pick an operation, fill the fields, read the answer. Nothing leaves the tab.

Every state is a link. Change a field and the address changes with it, so a curve and its question can go into a chat or an issue as is. Opening the link runs the same call again.

What does it show? The call twice, once as a `curves` command and once as the JSON a model sends. Then the answer, with the full tool response one click away.

## Polkadot keys too

The sr25519 tool is there with the other two. One chip loads the Substrate dev seed with `//Alice` hanging off it, and verify says yes to her signature over `hello`. Now hit `one bit off`. One flipped bit and it's a plain `false`.

Sign twice and you get two different signatures. Bug? No, that's schnorrkel mixing fresh randomness into the nonce. Both verify.

Keypair and derive start from exactly one key, so the `from` row picks which. Derive can start from a seed too, and its hard child shows a seed of its own. Ask for a hard child from a public key and the tool says no. Fair enough, hard needs the seed or the secret.

## BIP340 signatures

The `bip340 / verify` lead checks Schnorr signatures. The first chip loads a BIP340 vector with a message made from pi's hex digits. The signing key comes from e.

The empty message gets a signature too. Load that chip, then try `one bit off` for a plain `false`.

## Ed25519 signatures

The `RFC 8032 test 1` chip loads a signature over an empty message. Try `one bit off` for a plain `false`.

The `order 8 key` chip is a lousy key with a surprising signature. It verifies under ZIP 215. Tick the strict checkbox and it fails.
